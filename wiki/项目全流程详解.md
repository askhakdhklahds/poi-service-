## 1. 数据获取与入库

### 1.1 OSM POI

**方法/代码**

- 数据：OSM France 上海提取 `shanghai-latest.osm.pbf`。
- 导入：`ogr2ogr` + `scripts/osmconf_poi.ini` → 原始点表 `osm_points`。
- 清洗：`scripts/load_osm_poi.sql`：
  - 按 `amenity/shop/tourism/leisure/office/healthcare/public_transport` 等标签筛选；
  - 映射成 8 大类：餐饮、医院、学校、交通、购物、景点、商业、其他；
  - 同时生成 `geom(4326)`、`geom_4549`、`source_id = 'osm_' || osm_id`；
  - 写入 `poi_real`，再用 `switch_to_real_poi.sql` 切换成 `poi`。
- 小类：`scripts/add_sub_category.sql` 把大类细分为餐厅、咖啡、超市、公交站等。

**小例子**

```sql
SELECT count(*) FROM poi;                    -- 85864
SELECT category, count(*) FROM poi
GROUP BY category ORDER BY 2 DESC;
```

结果：餐饮、购物、医院、学校、交通、景点、商业、其他 8 类；黄浦区 2,772 个 POI。

### 1.2 行政区

**方法/代码**

- 数据：阿里云 DataV 上海行政区 GeoJSON。
- 导入：`scripts/import_districts.sql`：
  - `ST_MakeValid` 修复自相交；
  - `ST_CollectionExtract(..., 3)` 只取面；
  - `ST_Multi` 统一 MultiPolygon；
  - `ST_Transform(..., 4549)` 生成米制列。

**小例子**

```sql
SELECT count(*) FROM district;               -- 16
SELECT name FROM district ORDER BY adcode;   -- 黄浦区、徐汇区...
```

### 1.3 WorldPop 人口网格

**方法/代码**

- 数据：WorldPop 2020 中国 1km GeoTIFF（CC-BY-4.0）。
- 生成：`scripts/worldpop_to_grid.py`：
  - 用 `shanghai_districts.json` 的 bbox 裁剪；
  - `rasterio` 读取窗口；
  - 每个 1km 像元输出 `grid_x, grid_y, lon, lat, pop`；
  - 人口按像元求和，不取平均。
- 导入：`scripts/load_population_grid.sql`：
  - `\copy` 到 `population_grid_staging`；
  - 生成 4326/4549 几何；
  - `ST_Contains(district.geom, cell.geom)` 归属行政区；
  - 按七普 24,870,895 人统一校准。

**小例子**

```bash
python scripts/worldpop_to_grid.py \
  --src scripts/data/chn_pop_2020_1km.tif \
  --out scripts/data/pop_grid_1km.csv --factor 1
```

```sql
SELECT count(*) FROM population_grid;                     -- 15237
SELECT round(sum(pop)) FROM population_grid
WHERE district_adcode IS NOT NULL;                        -- 24870895
```

### 1.4 路网

**方法/代码**

- 原始路网：`road_raw` 211,721 条边。
- 拓扑：构建节点 `road_vertices`，给边分配 `source/target`。
- 最大连通分量：`road_main` 84,203 条边。
- `V5__route_network.sql`：
  - `road_car`：可驾车道路，按 `maxspeed`/道路等级算时间，`oneway` 控制方向；
  - `road_walk`：可步行道路，1.2m/s，台阶 0.8m/s。
- `V6__walk_fallback.sql`：
  - `road_walk_all`：步行不连通时回退到全市路网，快速路/主干道加 3 倍成本。

**小例子**

```sql
SELECT count(*) FROM road_car;        -- 81481
SELECT count(*) FROM road_walk;       -- 77965
SELECT count(*) FROM road_walk_all;   -- 84203
```

## 2. 数据库设计与索引

**方法/代码**

- 迁移：Flyway `V1`–`V6`。
- `poi`：
  - `geom geometry(Point,4326)`：交换、展示、点面归属；
  - `geom_4549 geometry(Point,4549)`：米制距离；
  - `source_id` 唯一：导入幂等；
  - `sub_category`：小类。
- `district`：`id` 主键，`adcode` 唯一业务键，`MultiPolygon`。
- `population_grid`：1km 人口网格，带 4326/4549 和 `district_adcode`。
- `facility_standard`：设施分类、步行阈值。
- 索引：

```sql
CREATE INDEX idx_poi_geom      ON poi USING GIST (geom);
CREATE INDEX idx_poi_geom_4549 ON poi USING GIST (geom_4549);
CREATE INDEX idx_poi_cat_4549  ON poi (category, geom_4549);
CREATE UNIQUE INDEX uq_poi_source_id ON poi (source_id);
```

**小例子**

```sql
EXPLAIN (ANALYZE, BUFFERS)
SELECT count(*) FROM poi_bench
WHERE ST_DWithin(geom_4549,
  ST_Transform(ST_SetSRID(ST_MakePoint(121.4737,31.2304),4326),4549), 1000);
```

- 无索引：690ms，Parallel Seq Scan。
- GiST：54.6ms，Bitmap Index Scan。
- 热缓存：约 22ms。

## 3. 空间查询流程

**方法/代码**

| 功能 | Controller | Service 方法 | SQL 关键 |
|---|---|---|---|
| 周边 | `PoiController.within` | `PoiService.within` | `ST_DWithin` |
| 最近邻 | `PoiController.nearest` | `PoiService.nearest` | `<->` |
| 缓冲区分组 | `AnalysisController.buffer` | `PoiService.bufferStats` | `ST_DWithin + GROUP BY` |
| 详情 | `PoiController.detail` | `PoiService.detail` | `ST_Contains` |
| 分类统计 | `PoiController.stats` | `PoiService.stats` | `GROUP BY category` |
| GeoJSON | `PoiController.geojson` | `PoiService.geoJsonSample` | `jsonb_agg` |

**周边查询 SQL**

```sql
WITH p AS (
  SELECT ST_Transform(ST_SetSRID(ST_MakePoint(?, ?), 4326), 4549) AS pt
)
SELECT id, name, category, sub_category,
       ROUND(ST_Distance(geom_4549, p.pt)) AS distance_m,
       ST_X(geom) AS lon, ST_Y(geom) AS lat
FROM poi, p
WHERE ST_DWithin(geom_4549, p.pt, ?)
ORDER BY distance_m
LIMIT ?;
```

**小例子**

```bash
curl "http://localhost:8081/api/poi/within?lon=121.4737&lat=31.2304&radius=1000&limit=5"
```

返回 5 条 POI，含 `distance_m`。实测 30 次：P50 15.91ms / P95 26.7ms（limit=200）。

**最近邻**

```sql
ORDER BY geom_4549 <-> p.pt LIMIT 10;
```

`<->` 走 GiST KNN 索引，10M 数据 0.37ms。

## 4. 行政区统计与缓存

**方法/代码**

- `DistrictService.stats`：
  - `@Cacheable(value="districtStats", key="#adcode")`；
  - 先查 `mv_district_stats`；
  - 物化视图不存在时回退实时 `LEFT JOIN + ST_Contains`。
- `DistrictService.list`：缓存行政区列表。
- `AdminController.refreshStats`：
  - 不存在则创建物化视图 + 唯一索引；
  - 存在则 `REFRESH MATERIALIZED VIEW CONCURRENTLY`；
  - 清 `districtStats` 缓存。

**小例子**

```bash
curl "http://localhost:8081/api/district/310101/stats"
# {"data":{"adcode":"310101","name":"黄浦区","poi_cnt":2772}}
```

- 实时聚合 10M：220ms；
- 物化视图：0.024ms；
- 接口冷启动 58ms → Redis 命中 25ms。

## 5. MVT 瓦片与 GeoServer

**方法/代码**

- 动态 MVT：`TileController` → `PoiService.tile`：
  - Caffeine 缓存 `z/x/y/category`；
  - `ST_TileEnvelope` → `ST_Intersects` 粗筛 → `ST_AsMVTGeom` → `ST_AsMVT`。
- 预生成瓦片：`StaticTileController` + `scripts/generate_tiles.py`，z9–13 共 708 张 `.pbf`。
- GCJ-02：`scripts/build_gcj_data.py` 偏移算法 → `poi_gcj` / `tiles-gcj`。
- GeoServer：`GeoServerService.publish` 通过 REST 创建 workspace/datastore/layers。

**小例子**

```bash
curl -o tile.mvt "http://localhost:8081/api/tiles/13/6860/3346.mvt"
# 实测 49,719 bytes，X-Tile-Cached: MISS
```

- 真实数据同范围 GeoJSON 227KB → MVT 49.7KB，降 78.6%。
- WMS 返回图片；WFS 返回矢量要素；WMTS 返回预切瓦片。

## 6. 异步导入

**方法/代码**

- `ImportController.upload`：保存临时 CSV → `createTask` 返回 taskId → `@Async` 后台执行。
- `ImportService.process`：
  1. `UPDATE import_task SET status='RUNNING'`；
  2. `CopyManager.copyIn` 把 CSV 灌进 `poi_staging`；
  3. 一条 `INSERT ... SELECT` 生成几何、转投影、校验、`ON CONFLICT (source_id) DO NOTHING`；
  4. 更新 SUCCESS/FAILED。
- `AsyncConfig`：core 2 / max 4 / queue 50 / 线程名前缀 `import-`。
- `ImportBenchmarkService`：row / batch / copy 三种方式。

**小例子**

```bash
curl -F "file=@poi.csv" http://localhost:8081/api/import/poi
# {"taskId": 1}
curl "http://localhost:8081/api/import/tasks/1"
```

5 万行实测：逐条 14.7s、Batch 6.8s、COPY+staging 9.8s。

## 8. 15 分钟生活圈

> 深度版：[15 分钟生活圈详解](15分钟生活圈详解.md)（WorldPop 处理、入库 SQL、覆盖 SQL、API、前端、两个完整例子、可视化测试）

**方法/代码**

- 数据：`population_grid`（1km 网格，七普校准）。
- `facility_standard`：医疗/教育/商业/文体/交通 5 类。
- `CoverageService.coverage`：
  - 步行半径 = `thresholdSeconds × 1.2`；
  - `covered` CTE：`population_grid JOIN poi ON ST_DWithin(geom_4549, ..., radius)`；
  - 汇总 `popTotal / popCovered / coverageRatio / gapPopulation`；
  - 返回 FeatureCollection：绿色覆盖格、红色盲区格；
  - Redis 缓存键 `adcode:category:threshold`。
- `LifeCircleController`：`GET /api/life-circle/categories`、`/coverage`。
- `life-circle.html`：行政区/设施/5-10-15 分钟 + 覆盖网格 + 摘要卡片。

**小例子**

```bash
curl "http://localhost:8081/api/life-circle/coverage?adcode=310101&category=healthcare&threshold=900"
```

实测：

| 区域 | 设施 | 覆盖率 | 覆盖人口 | 盲区人口 | 网格 |
|---|---|---|---:|---:|---:|
| 黄浦区 | 医疗 | 97.2% | 658,413 | 19,060 | 27 |
| 浦东新区 | 医疗 | 31.9% | 1,711,833 | 3,647,388 | 1,816 |
| 黄浦区 | 教育 10 分钟 | 57.1% | — | — | 27 |

**前端可视化**

- `/life-circle.html`：选择黄浦区 + 医疗 + 15 分钟；
- 地图显示绿色覆盖格、红色盲区格；
- 摘要卡片显示覆盖人口、覆盖率、盲区人口、网格数；
- CDP 验证：网格图层存在且渲染，摘要与 API 一致，截图 `shot_life_circle_cdp.png`。

**局限**

- 欧氏半径，不是路网等时圈；
- WorldPop 1km 旧版偏高，按七普总人口校准；
- 人口是模型估计，不是真实居民出行调查。

## 9. 多路线对比

**方法/代码**

- **首选 Valhalla 高精度路网**：`ValhallaRouteService` 调公共 `/route`，`costing=auto|pedestrian`、`alternates`、polyline6；8s 超时。
- **本地兜底**：`RoutePlanService.externalOrLocal()` 先调 Valhalla，失败/空结果回退本地。
  - `pgr_ksp` 每个模式取 K 条候选；
  - 按边集合 Jaccard 去重（>0.8 视为重复）；
  - 最多 3 条驾车 + 3 条步行；
  - 每条统计距离、时间、道路构成、150m 沿途 POI、行政区、摘要；
  - Redis 缓存 `routePlan`。
- `RouteController`：`POST /api/route/plan`。
- `route.html`：地图多色路线 + 路线卡片（距离/时间/来源标签）+ 高亮。
- Agent：`route_compare` 工具 + `RoutePlanningAgent` + `routePlanUrl`。

**小例子**

```bash
POST /api/route/plan
{
  "from": {"lon": 121.4737, "lat": 31.2304, "name": "人民广场"},
  "to":   {"lon": 121.4855611, "lat": 31.2393233, "name": "外滩"},
  "modes": ["car","walk"],
  "alternatives": 3
}
```

实测（Valhalla）：

```
3 条驾车 + 3 条步行
驾车最快：2.9 km / 11 分钟（西藏中路→九江路→河南中路→北京东路→中山东一路）
步行推荐：2.0 km / 27 分钟
来源标记：source=valhalla, sourceLabel=高精度路网
冷启动：1.1–2.3s；Redis 命中：约 60ms
```

本地兜底（Valhalla 不可用时）：

```
3 条驾车 + 3 条步行
冷启动：约 688ms
缓存 15 次：P50 3.73ms / P95 28.69ms
```

**路径特点示例**

```
高精度路线（Valhalla/OSM）：全程 2.9 公里，预计驾车 11 分钟；沿途餐饮 50 个，穿过黄浦区。
```

**局限**

- 公共 Valhalla 实例可能限流/不可用，已做超时与本地兜底；
- 时间未考虑实时路况/红绿灯；
- 本地兜底 `maxspeed` 大量为空，用默认车速；
- 步行不连通时回退全市路网；
- 沿途 POI 是 150m 缓冲的启发式统计；
- 生产应自建 Valhalla/OSRM。

## 10. 工程化

**方法/代码**

- 认证：`SecurityConfig` + `JwtAuthFilter` + `JwtService`，无状态 JWT。
- 授权：RBAC，`/api/admin/**` → ADMIN，`/api/import/**` → ADMIN/ANALYST。

- 监控：Actuator + Micrometer + Prometheus + 自定义瓦片指标。
- 慢查询：`pg_stat_statements` + `/api/admin/slow-queries`。
- 测试：JUnit 5 + MockMvc + Testcontainers。
- 部署：Dockerfile + Docker Compose + GitHub Actions。

## 13. 完整流程串讲

> 数据侧：OSM 上海 PBF 经 ogr2ogr 导入原始点，按标签筛出 85,864 条 POI；DataV 边界清洗成 16 个区；WorldPop 1km 人口落到 15,237 个网格并按七普校准；OSM 路网提取最大连通分量，再拆成驾车/步行两套路网。
>
> 查询侧：Spring Boot 通过 JdbcTemplate 直接查 PostGIS；周边用 ST_DWithin，最近邻用 `<->`，行政区用 ST_Contains；10M 数据从 690ms 优化到 54.6ms。
>
> 分析侧：行政区统计走物化视图 + Redis；生活圈用 ST_DWithin 按人口加权算覆盖率和盲区；多路线用 pgr_ksp + Jaccard 去重，输出车/人路线和沿途特点。
>
> 服务侧：MVT 瓦片给前端，GeoServer 补 WMS/WFS；CSV 异步导入用 COPY + staging + ON CONFLICT。
>
> Agent 侧：Orchestrator 做意图、路由、执行、校验、汇总；4 大类意图、4 个角色、11 个工具；LLM 只负责理解表达，空间计算交给确定性 SQL；多轮记忆、工具轨迹、成功率都可查。
>
> 工程侧：JWT/RBAC、Bucket4j 限流、Redis/Caffeine、Actuator/Prometheus、MockMvc/Testcontainers、Docker Compose/CI。
