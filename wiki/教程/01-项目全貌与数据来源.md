# 01 项目全貌与数据来源

## 目标

知道项目解决什么问题、数据从哪来、真实数据与合成数据怎么区分。

## 项目定位

> 城市 POI 空间分析平台：回答“附近有什么、最近的是谁、某个区的设施怎么分布、居民 15 分钟内能不能到”。

三条能力线：

1. **空间查询**：周边、最近邻、缓冲区、点面归属。
2. **地图服务**：MVT 瓦片、GeoServer WMS/WFS。
3. **空间 Agent 与评估**：自然语言问答、路线规划、15 分钟生活圈覆盖。

## 数据来源

| 数据 | 来源 | 数量 | 用途 |
|---|---|---|---|
| `poi` | OSM France 上海提取 | 85,864 | 真实业务/演示 |
| `district` | 阿里云 DataV | 16 个区 | 行政区统计 |
| `poi_bench` | 程序生成 | 10,010,000 | 只做规模压测 |
| `road_raw` / `road_main` | OSM 上海路网 | 211,721 / 84,203 条边 | pgRouting |
| `population_grid` | WorldPop 2020 1km | 15,237 个网格 | 生活圈人口 |

## 真实数据链路

```
上海 OSM PBF
  → ogr2ogr + osmconf_poi.ini
  → osm_points（141,841）
  → load_osm_poi.sql 按 POI 标签筛选
  → poi（85,864）
```

行政区：

```
DataV GeoJSON → district_raw
  → import_districts.sql（MakeValid / CollectionExtract / Multi / Transform）
  → district（16）
```

人口：

```
WorldPop 1km GeoTIFF → worldpop_to_grid.py
  → pop_grid_1km.csv → load_population_grid.sql
  → population_grid（15,237）
  → 按七普 24,870,895 统一校准
```

## 面试口径

> 演示和业务查询用 85,864 条真实上海 OSM POI，行政区是真实的 DataV 边界；另外用 1000 万条合成数据专门做规模压测，两套数据分开，不会拿合成数据冒充真实业务。
