# 13 多路线对比（车/人 + 沿途特点）

## 目标

能讲清 A→B 多路线、驾车/步行两套路网、`pgr_ksp`、多样性去重和沿途特点统计。

## 解决什么问题

原来的路线是“从起点出发访问多个景点”的贪心排序，不是 A→B 的多方案对比，也没有车/人区分。

现在要回答：

> 从外滩到陆家嘴怎么走？给我几条驾车和步行路线，地图上画出来，并说明每条路线经过什么。

## 高精度路线：Valhalla + 本地兜底

自建 `road_car` / `road_walk_*` 只有上海 OSM 抽取的一部分边，且 `maxspeed`、`oneway` 大量缺失，路线会出现“贴直线”或绕行不自然。为了提升路线效果，接入 **Valhalla 公共路由服务**（OSM 全量路网）作为首选，本地 pgRouting 作为兜底。

`service/route/ValhallaRouteService.java`：

```
planMode(mode, from, to, alternatives)
  → POST https://valhalla1.openstreetmap.de/route
    { locations: [{lat,lon},{lat,lon}],
      costing: auto | pedestrian,
      alternates: alternatives-1 }
  → 解析 trip.summary.length(km) / trip.summary.time(s)
  → 解析 legs[0].shape（polyline6）为 GeoJSON LineString
  → 用本地 PostGIS 继续算沿途 POI / 行政区 / 摘要
```

`RoutePlanService` 的取数顺序：

```java
private List<Map<String,Object>> externalOrLocal(String mode, RoutePoint from,
                                                 RoutePoint to, int k) {
    List<Map<String,Object>> external = valhalla.planMode(mode, from, to, k);
    return external.isEmpty() ? planMode(mode, from, to, k) : external;
}
```

配置（`application.yml`）：

```yaml
route:
  valhalla:
    enabled: ${ROUTE_VALHALLA_ENABLED:true}
    base-url: ${VALHALLA_BASE_URL:https://valhalla1.openstreetmap.de}
    timeout-seconds: ${VALHALLA_TIMEOUT:8}
```

设计要点：

- **外部服务只负责“几何 + 距离 + 时间”**，沿途富化仍用本地 PostGIS，避免外部接口不可控。
- `RestClient` 超时 8s；任何异常/空结果都返回空列表，自动回退本地 `pgr_ksp`，不影响接口可用性。
- 返回字段增加 `source: "valhalla"`、`sourceLabel: "高精度路网"`，前端路线卡片显示来源标签。
- `costing=auto` 对应驾车，`pedestrian` 对应步行；本次验证步行 人民广场→外滩 2.0 km / 27 分钟，驾车 2.9 km / 11 分钟，符合实际。

**为什么不自己部署 Valhalla？** 实习项目用公共实例足够演示；生产应自建（上海 OSM 抽取 + Valhalla Docker），避免公共实例限流和可用性风险。

## 两套路网

`V5__route_network.sql`：

- `road_car`：81,481 条边；按 `maxspeed` 或道路等级算时间；`oneway` 控制方向。
- `road_walk`：77,965 条边；步行 1.2 m/s，台阶 0.8 m/s。
- `V7__walk_network_v2.sql` 的 `road_walk_v2`：76,824 条边；排除 path/track，优先人行道/居住区道路，service/主干道加惩罚。
- `V6__walk_fallback.sql` 的 `road_walk_all`：可步行路网不连通时回退到全市路网，并对快速路/主干道加 3 倍步行成本。

为什么不能只用一套路网？

- 驾车不能走 footway/path/pedestrian/steps；
- 步行不能走 trunk/motorway；
- `oneway` 对车有方向约束，对步行基本没有。

## 多路径

`service/route/RoutePlanService.java`：

```sql
WITH ksp AS (
  SELECT * FROM pgr_ksp(
    'SELECT id, source, target, cost, reverse_cost FROM road_car',
    ?, ?, ?, directed := true
  )
)
SELECT k.path_id, k.path_seq, k.edge, e.highway, e.length_m, e.cost,
       ST_AsGeoJSON(e.geom) AS geojson
FROM ksp k JOIN road_car e ON e.id = k.edge
WHERE k.edge <> -1
ORDER BY k.path_id, k.path_seq;
```

- `pgr_ksp` 取 K 条候选；
- 按边集合 Jaccard 去重，相似度 > 0.8 视为重复；
- 最多返回 3 条驾车 + 3 条步行。

## 沿途特点

每条路线统计：

1. 距离：`sum(length_m)`；
2. 预计时间：`sum(cost)`（cost 已按车速/步速换算成秒）；
3. 道路类型构成：按 `highway` 分组求长度占比；
4. 沿途 POI：`ST_DWithin(poi.geom_4549, route_geom_4549, 150)`，按分类计数；
5. 经过行政区：`ST_Intersects(district.geom, route_geom)`；
6. 一句话摘要：由上面真实统计拼出来。

## API

```
POST /api/route/plan
{
  "from": {"lon": 121.49, "lat": 31.24, "name": "外滩"},
  "to":   {"lon": 121.50, "lat": 31.24, "name": "陆家嘴"},
  "modes": ["car", "walk"],
  "alternatives": 3
}
```

返回 `routes[]`，每条包含：

- `mode`、`label`、`distanceMeters`、`durationSeconds`；
- `geometry`（GeoJSON LineString）；
- `highlights.roadTypes / pois / districts / summary`；
- `source` / `sourceLabel`：`valhalla` / `高精度路网`，或本地 `pgr_ksp` 时缺省；
- 步行回退时带 `fallback`、`fallbackNote`。

## Agent 接入

- `IntentRecognizer`：`从A到B怎么走` → `ROUTE`，entities 带 `from`、`to`。
- “从”是可选的，所以“人民广场到外滩怎么走”也能出路线；也支持 `A→B`。
- `RoutePlanningAgent`：解析地点 → `ToolRegistry.route_compare` → `RoutePlanService`。
- 返回 `answer`、`cards`、`routePlanUrl`。
- `agent.html` 显示“查看多路线对比”链接。

## 实测

| 场景 | 数字 |
|---|---|
| 人民广场→外滩（Valhalla） | 3 条驾车 + 3 条步行 |
| 驾车最快 | 2.9 km / 11 分钟（西藏中路→九江路→河南中路→北京东路→中山东一路） |
| 步行推荐 | 2.0 km / 27 分钟 |
| 路线接口（Valhalla 冷） | 约 1.1–2.3s |
| 路线接口（Redis 命中） | 约 0.02–60ms |
| 外滩→陆家嘴（本地兜底） | 3 条驾车 + 3 条步行 |

## 局限

- 公共 Valhalla 实例可能限流/不可用，已做 8s 超时 + 本地兜底；
- 时间未考虑实时路况、红绿灯，Valhalla 的 `auto` 是历史/标称速度；
- 本地兜底路网 `maxspeed` 大部分为空、`oneway` 有缺失，方向可能不完全准确；
- 步行路网可能不连通，会回退到全市路网；
- 沿途 POI 是 150m 缓冲的启发式统计，不是真实“沿途体验”；
- 公共实例不能用于生产，生产需自建 Valhalla/OSRM。

## 面试问答

**Q：多路线怎么做的？**

A：两套路网 + `pgr_ksp` 多候选 + 边集合 Jaccard 去重；驾车和步行分别返回最多 3 条。

**Q：车/人怎么区分？**

A：不是前端切开关，而是 `road_car` 和 `road_walk` 两套表：道路过滤不同、速度不同、`oneway` 约束不同。

**Q：沿途特点怎么算？**

A：路线几何做 150m 缓冲，统计 POI 分类；再叠加道路类型和行政区，最后由这些真实统计拼摘要。

**Q：为什么有时间估计但不保证准确？**

A：没有实时路况、红绿灯和转向限制，`maxspeed` 也大量缺失，所以只能做估算，不能当生产导航。

**Q：为什么要接 Valhalla，原来的 pgRouting 不行吗？**

A：原来的 `road_car` / `road_walk` 只是上海 OSM 抽取的子集，`maxspeed`、`oneway` 缺失多，路线质量不稳定。Valhalla 用完整 OSM 路网和成熟代价模型，能给出更自然的车/人路线；本地 pgRouting 保留为兜底，外部不可用时接口仍可用。

**Q：外部服务挂了怎么办？**

A：`ValhallaRouteService` 捕获所有异常并返回空列表，`RoutePlanService` 自动回退到 `pgr_ksp`；同时 8s 超时避免拖垮接口。这是典型的“外部依赖 + 降级”设计。
