# 07 异步导入

## 目标

能讲清 CSV 上传 → taskId → 后台 COPY → 幂等写入 → 进度轮询的全过程，以及线程池参数。

## 入口

`controller/ImportController.java`：

```java
Path tmp = Files.createTempFile("poi-import-", ".csv");
file.transferTo(tmp);
long taskId = service.createTask(file.getOriginalFilename());
service.process(taskId, tmp);
return Map.of("code", 0, "message", "accepted", "taskId", taskId);
```

`process` 是 `@Async("importExecutor")`，接口立即返回。

## 后台处理

`service/ImportService.java`：

1. `UPDATE import_task SET status='RUNNING'`。
2. 统计行数。
3. `TRUNCATE poi_staging`。
4. `CopyManager.copyIn` 把 CSV 灌进 staging。
5. 一条 `INSERT ... SELECT`：

```sql
INSERT INTO poi (name, category, lng, lat, geom, geom_4549, source_id)
SELECT name, category, lng, lat,
       ST_SetSRID(ST_MakePoint(lng, lat), 4326),
       ST_Transform(ST_SetSRID(ST_MakePoint(lng, lat), 4326), 4549),
       source_id
FROM poi_staging
WHERE name IS NOT NULL AND category IS NOT NULL
  AND lng BETWEEN -180 AND 180 AND lat BETWEEN -90 AND 90
ON CONFLICT (source_id) DO NOTHING;
```

6. 更新 SUCCESS / FAILED。
7. 删除临时文件。

## 三个设计点

- **staging**：COPY 只负责快速卸货，几何生成/校验/去重放一条 SQL。
- **幂等**：`source_id` 唯一 + `ON CONFLICT DO NOTHING`。
- **可追踪**：任务表记录 status/error_msg/finished_at。

## 线程池

`config/AsyncConfig.java`：

```java
executor.setCorePoolSize(2);
executor.setMaxPoolSize(4);
executor.setQueueCapacity(50);
executor.setThreadNamePrefix("import-");
```

- 2 个核心线程；50 个排队；最多扩到 4 个。
- 第 55 个任务触发默认 AbortPolicy，抛 `TaskRejectedException`。
- 默认 `waitForTasksToCompleteOnShutdown=false`，停机时队列任务可能丢。

## 三种导入方式（2026-11-16 本机复测）

| 模式 | 耗时（5 万行） | 吞吐 |
|---|---|---|
| row | 11.3–16.3s | 约 3,100–4,400 行/秒 |
| batch | 3.9–4.2s | 约 11,900–12,800 行/秒 |
| copy | 2.7s | 约 18,500 行/秒 |

**面试口径**：本次复测 COPY + staging 最快，batch 次之，逐条最慢；历史一次测到 copy 9.8s，说明结论会受缓存、并行度和 staging 转换开销影响。能确定的结论是“批量远快于逐条”，不要把 COPY 说成永远最快或永远最慢。

## 不足

- `TRUNCATE poi_staging` 是全局的，并发导入会互相踩。
- `total - success` 会把“重复被跳过”算成失败。
- 没有重试、死信、断点续传。

## 面试问答

**Q：为什么异步？**

A：大文件导入耗时长，先返回 taskId，前端轮询。

**Q：怎么保证不重复？**

A：`source_id` 唯一 + `ON CONFLICT DO NOTHING`。

**Q：线程池怎么定？**

A：导入是 IO/DB 密集型，core 2 / max 4 / queue 50 是保守值；生产加优雅关闭、拒绝策略和监控。
