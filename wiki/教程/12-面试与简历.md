## 2 分钟介绍

> 我做的是一个城市 POI 空间分析平台，解决“附近有什么、某个区域的设施怎么分布、居民 15 分钟内能不能到”这类问题。
>
> 数据侧导入了 85,864 条真实上海 OSM POI 和 16 个真实行政区，另外用 1000 万条合成数据做规模压测；设计了 4326 存储 + 4549 米制投影的双列模型，并建 GiST 索引。
>
> 查询侧周边用 ST_DWithin，因为能用 GiST 做包围盒预筛；最近邻用 <-> KNN。真实数据接口 P95 8.5ms；1000 万数据从无索引 690ms 优化到 54.6ms。
>
> 统计侧行政区实时聚合要 220ms，我用物化视图降到 0.024ms，再叠 Redis，接口 25ms。
>
> 地图侧用 ST_AsMVT 出矢量瓦片，体积比 GeoJSON 降 75%~79%；GeoServer 通过 REST 自动发布 WMS/WFS。
>
> Agent 侧我参考 EchoMind 的结构做了精简重构：Orchestrator 负责意图、路由、执行、校验、汇总；四个角色分别处理通用问答、空间查询、路线规划和报告；工具通过 ToolRegistry 做白名单、超时和统计；LLM 只负责理解和表达，空间计算全部交给确定性 SQL 工具。
>
> 最近加了 15 分钟生活圈评估：把 WorldPop 人口落到 1km 网格，按七普人口校准，用 ST_DWithin 算覆盖率和盲区。黄浦区医疗覆盖率 97.2%，浦东新区 31.9%。
>
> 整体是 Spring Boot 3 + PostGIS + Redis + Docker Compose，能部署、能监控、能测试。

## STAR

- **T**：独立完成数据入库、空间查询、分析、地图服务、Agent 和评估页面。
- **A**：双列坐标模型 + GiST + ST_DWithin + KNN + 物化视图 + Redis + MVT + pgRouting + EchoMind 风格 Agent + WorldPop 生活圈。
- **R**：10M 查询 690ms→54.6ms；统计 220ms→0.024ms；MVT 降 75%~79%；生活圈覆盖接口 17–245ms。
