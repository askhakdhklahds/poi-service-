# 10 工程化与监控

## 目标

能讲清 JWT/RBAC、限流、缓存分工、监控、测试和部署。

## JWT + RBAC

- 登录：`POST /api/auth/login` → JWT（含用户名、角色、过期时间）。
- 请求：`Authorization: Bearer <token>` → `JwtAuthFilter` → SecurityContext。
- 无状态：`SessionCreationPolicy.STATELESS`，关闭 CSRF/formLogin/httpBasic。

权限：

| 路径 | 权限 |
|---|---|
| 静态页面、`/tiles/**`、`/api/poi/**`、`/api/life-circle/**` | 公开 |
| `/api/agent/**` | 公开（演示） |
| `/api/import/**` | ADMIN / ANALYST |
| `/api/admin/**` | ADMIN |

不足：内存用户、默认密钥、CORS 全开；生产接数据库/LDAP，环境变量注入密钥。

## 限流

`config/RateLimitFilter.java`：

- Bucket4j 令牌桶，每 IP 120 请求/分钟。
- `@Order(HIGHEST_PRECEDENCE)`，在 Security 前执行。
- 超限 429。

不足：内存桶，多实例不共享；反向代理后要解析 `X-Forwarded-For`。

## 缓存分工

| 缓存 | 存什么 | 配置 |
|---|---|---|
| Redis | 行政区统计、生活圈覆盖 | TTL 5 分钟，`@Cacheable` |
| Caffeine | MVT 瓦片 | 1 万张 / 10 分钟 / recordStats |

一致性：TTL + 刷新物化视图时清缓存；生活圈导入数据后要清 `lifeCircleCoverage`。

## 监控

- Actuator：`health/info/metrics/prometheus`。
- 自定义 Gauge：瓦片命中率、命中数、未命中数、缓存大小。
- 慢查询：`pg_stat_statements` + `/api/admin/slow-queries`。
- Agent：`/api/agent/monitor`、`/api/agent/trace/{requestId}`。

## 部署

- `Dockerfile` 多阶段构建。

## 面试问答

**Q：JWT 和 session 区别？**

A：JWT 无状态，适合前后端分离和多实例；session 需要服务端存储。

**Q：令牌桶和固定窗口？**

A：令牌桶允许短时突发到容量，按速率补充；固定窗口边界可能出现双倍突发。

**Q：为什么统计用 Redis、瓦片用 Caffeine？**

A：统计跨实例共享、变化慢；瓦片体积大、访问频繁、允许本地不一致。

**Q：为什么用 Testcontainers？**

A：H2 没有 PostGIS 的 `ST_DWithin`、GiST、`ST_Contains`，测了也不能证明生产可用。
