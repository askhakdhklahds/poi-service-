## 双列模型

```sql
geom      geometry(Point, 4326) NOT NULL,
geom_4549 geometry(Point, 4549)
```

| 列 | 用途 |
|---|---|
| `geom` | 国际交换、GeoJSON、WMS/WFS、点面归属 |
| `geom_4549` | CGCS2000 3 度带，单位米，距离/面积 |

为什么不再每次 `ST_Transform`：

- 每次查询要对每行变换，CPU 开销大；
- 列上套函数会让 GiST 索引失效；
- 预计算成列后直接 `ST_DWithin`。

其他城市：北京 4548、武汉 4547、东北 4550。

## 索引

```sql
CREATE INDEX idx_poi_geom      ON poi USING GIST (geom);
CREATE INDEX idx_poi_geom_4549 ON poi USING GIST (geom_4549);
CREATE INDEX idx_poi_category  ON poi (category);
CREATE INDEX idx_poi_cat_4549  ON poi (category, geom_4549);
CREATE UNIQUE INDEX uq_poi_source_id ON poi (source_id);
```

GiST = filter-and-refine：先按 MBR 粗筛，再精确判断。

## 行政区表

- 主键是 `id`，不是 `adcode`。
- `adcode` 是唯一业务键。
- `geom` / `geom_4549` 都是 `MultiPolygon`，能装飞地/岛屿。

## 物化视图

`mv_district_stats`：预聚合每个区的 POI 数量。

- 实时 JOIN + 聚合 10M：220ms。
- 查物化视图：0.024ms。
- `REFRESH ... CONCURRENTLY` 需要唯一索引。

## 生活圈表

- `population_grid`：1km 人口网格，带 4326/4549 几何和 `district_adcode`。
- `facility_standard`：设施分类、步行阈值、欧氏半径。

## 练习

```sql
-- 看执行计划
EXPLAIN (ANALYZE, BUFFERS)
SELECT count(*) FROM poi_bench
WHERE ST_DWithin(geom_4549,
  ST_Transform(ST_SetSRID(ST_MakePoint(121.4737,31.2304),4326),4549), 1000);

-- 看索引
SELECT indexname, indexdef FROM pg_indexes WHERE tablename='poi';

-- 看网格
SELECT district_adcode, count(*), round(sum(pop))
FROM population_grid GROUP BY district_adcode ORDER BY 3 DESC LIMIT 5;
```
