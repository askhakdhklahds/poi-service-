# 11 性能实测与数字口径

## 目标

能说清每个数字怎么测的、代表什么、不能代表什么。

## 2026-11-16 本机复测（面试优先用这组）

| 场景 | 复测结果 |
|---|---|
| 10M `ST_DWithin` 无索引 | 约 1.19s（Parallel Seq Scan） |
| 10M `ST_DWithin` + GiST | 热缓存 24–139ms（中位约 27ms），冷缓存约 244ms |
| KNN `<->` | 0.177ms |
| 行政区实时聚合（真实 85,864 POI） | 热缓存 73–76ms，冷缓存约 756ms |
| 物化视图查询 | 0.014ms |
| 5 万行导入 | row 11.3–16.3s / batch 3.9–4.2s / copy 2.7s |
| 动态 MVT z13 | 49.7KB；同范围 GeoJSON（含属性）约 248KB，降约 79% |
| 功能用例 | 139/139（真实数据套件）；30/30（快速套件）；自动化用例 21 通过、1 跳过 |
| 生活圈 | 黄浦 97.2%、浦东 31.9%（与历史一致） |
| 路线 | 人民广场→外滩 驾车约 3.0km/10min、步行约 2.0km/26min |

> 历史表保留作对比。性能数字受缓存、并行度、机器负载和数据分布影响；面试时优先说“复测区间 + 测法”，不要只报单点最优值。

## 空间查询

| 场景 | 数字 | 测法 |
|---|---|---|
| 10M `ST_DWithin` 无索引 | 690ms | `DROP INDEX` + `EXPLAIN ANALYZE`，Parallel Seq Scan |
| 10M `ST_DWithin` + GiST（冷） | 54.6ms | 建 GiST，Bitmap Index Scan |
| 同上（热） | 约 22ms | 重复执行，热缓存 |
| `ST_Distance < 1000`（反例） | 879ms | Parallel Seq Scan |
| KNN `<->` | 0.37ms | Index Scan，只读 10 行 |
| 真实数据周边接口 | P50 4.1 / P95 8.5 / P99 10.4ms | curl 串行 50 次 |
| 10M 周边接口 | P50 34.5 / P95 50.9ms | curl 串行 50 次 |
| JMeter 50 并发 × 20 | 181 QPS / P95 43ms / 0 错误 | 本机 |

**口径**：SQL 层和接口层分开；接口 P95 包含 `ST_AsGeoJSON`、JSON 序列化、网络和连接开销。

## 复现

:: 接口延迟
1..50 | % { (Measure-Command { Invoke-WebRequest "http://localhost:8081/api/poi/within?lon=121.4737&lat=31.2304&radius=1000&limit=200" | Out-Null }).TotalMilliseconds }

## 不能乱说

- 不说“生产级高并发”：本机 50 并发、单机环境。
- 不把 1000 万合成数据说成真实业务。
- 不把生活圈说成真实居民出行调查。
- 不编没测过的 QPS、准确率、召回率。
