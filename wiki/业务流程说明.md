# 业务流程说明

## 1. 数据从哪来

```
OSM 上海 PBF
  → ogr2ogr + osmconf_poi.ini
  → osm_points（141,841 个原始点）
  → load_osm_poi.sql 按 POI 标签筛选
  → poi（85,864 条真实 POI）
  → add_sub_category.sql 补小类

DataV 行政区 GeoJSON
  → district_raw
  → import_districts.sql（MakeValid / CollectionExtract / Multi / Transform）
  → district（16 个区）

OSM 路网
  → road_raw（211,721 条边）
  → 构建节点 + source/target
  → 最大连通分量 road_main（84,203 条边）

WorldPop 2020 1km
  → worldpop_to_grid.py
  → pop_grid_1km.csv（15,237 个网格）
  → load_population_grid.sql
  → population_grid（9,422 个网格落在区内，校准到 24,870,895 人）
```

## 2. 一条 POI 请求怎么走

以 `/api/poi/within` 为例：

```
浏览器
  → RateLimitFilter：按 IP 令牌桶，120/分钟
  → Spring Security：GET /api/poi/** 放行
  → PoiController.within：校验经纬度，半径夹 1–50km，limit 夹 1–500
  → PoiService.within
  → SQL：参数点 ST_Transform 到 4549 → ST_DWithin 过滤 → ST_Distance 排序
  → JdbcTemplate 返回 List<Map>
  → Jackson 序列化 {"code":0,"message":"ok","data":[...]}
```

## 3. 一条 MVT 请求怎么走

```
MapLibre
  → GET /api/tiles/{z}/{x}/{y}.mvt?category=
  → TileController：Caffeine 缓存键 z/x/y/category
  → 未命中 → PoiService.tile
  → ST_TileEnvelope(3857)
  → ST_Intersects(poi.geom, tile 范围转 4326) 粗筛
  → ST_AsMVTGeom 转瓦片坐标 + 裁剪
  → ST_AsMVT 编码 Protobuf
  → 响应头 X-Tile-Cached: HIT/MISS
```

预生成方案：

```
generate_tiles.py
  → z9–13 共 708 张 .pbf
  → StaticTileController 直接读磁盘
  → Cache-Control: 7 天
```

## 4. 一条 Agent 请求怎么走

```
POST /api/agent/ask {"question":"那餐厅呢","sessionId":"xxx"}
  → AgentController
  → AgentOrchestrator
  → ConversationStore.rewrite：
       上下文 place=黄浦区 → 改写成“在黄浦区附近 那餐厅呢 餐饮”
  → IntentRecognizer：
       NEARBY + category=餐饮 + radius=1000
  → AgentProfiles：SPATIAL_QUERY
  → SpatialQueryAgent：
       district_center(黄浦区) → pois_within(121.48,31.23,1000,餐饮,10)
  → AnswerVerifier：有工具证据、答案非空
  → ResponseComposer：透传
  → ConversationStore：保存 user/assistant + 上下文
  → TraceStore / AgentMonitor：记录工具轨迹和耗时
  → 返回 {intent,agentType,answer,data,center,radius,steps,cards,...}
```

### 角色路由

| 意图 | 角色 | 典型问题 |
|---|---|---|
| QUERY | SPATIAL_QUERY | 附近/最近/统计/排名/对比 |
| ROUTE | ROUTE_PLANNING | A→B 多路线、车/人 |
| REPORT | REPORT | 生成诊断报告 |
| GENERAL | GENERAL | 问候、能力介绍、兜底 |

## 4.1 多路线对比怎么走

```
route.html
  → 输入地名 → GET /api/poi/search（POI + 行政区，下拉建议）
     → 选中 → 打点 + flyTo 定位 → 两个都选好自动规划
  → 或地图选起点/终点（或 URL 参数）
  → POST /api/route/plan
  → RoutePlanService.externalOrLocal()：
       ValhallaRouteService → /route（auto | pedestrian），8s 超时
       失败/空结果 → 本地 pgr_ksp 兜底：
         road_car  → pgr_ksp，directed=true
         road_walk_v2 → pgr_ksp，directed=false
         不连通 → road_walk / road_walk_all 回退
  → 按边集合 Jaccard 去重，取 3 驾车 + 3 步行
  → 每条路线：距离/时间/道路构成/150m 沿途 POI/行政区（本地 PostGIS 富化）
  → 地图多色绘制 + 路线卡片（含 sourceLabel）
```

Agent 侧：

```
“从外滩到陆家嘴怎么走”
  → IntentRecognizer：ROUTE，entities.from=外滩，to=陆家嘴
  → RoutePlanningAgent
  → ToolRegistry.route_compare
  → RoutePlanService
  → answer + cards + routePlanUrl
  → agent.html 显示“查看多路线对比”链接
```

> 提问支持 `从A到B` / `A到B` / `A→B`；路线页显示起点/终点文字标签、总览和预计时间。

## 5. 生活圈评估怎么走

```
life-circle.html
  → /api/district/list 获取 16 个区
  → /api/life-circle/categories 获取 5 类设施标准
  → 用户选择：黄浦区 + 医疗 + 15 分钟
  → GET /api/life-circle/coverage?adcode=310101&category=healthcare&threshold=900
  → CoverageService：
       radius = 900 × 1.2 = 1080 米
       covered = population_grid JOIN poi ON ST_DWithin(..., radius)
       汇总 popTotal / popCovered / coverageRatio / gapPopulation
       生成 FeatureCollection（绿色覆盖 / 红色盲区）
  → Redis 缓存 lifeCircleCoverage::310101:healthcare:900
  → 页面渲染网格 + 摘要卡片
```

实测：黄浦区医疗 15 分钟覆盖率 97.2%，覆盖人口 658,413，盲区 19,060；浦东新区医疗 31.9%，盲区 3,647,388。

## 6. 异步导入怎么走

```
POST /api/import/poi（multipart CSV）
  → 保存临时文件
  → import_task 插入 PENDING，返回 taskId
  → @Async("importExecutor")
  → RUNNING
  → COPY 进 poi_staging
  → INSERT INTO poi SELECT ... 生成几何 + ON CONFLICT DO NOTHING
  → SUCCESS / FAILED
前端轮询 GET /api/import/tasks/{id}
```

## 7. 数字口径

| 数字 | 口径 |
|---|---|
| 85,864 | 真实 OSM POI，业务查询/演示 |
| 10,010,000 | 合成 `poi_bench`，只做规模压测 |
| 15,237 / 9,422 | WorldPop 1km 网格总数 / 落在上海区内的网格数 |
| 24,870,895 | 2020 年七普上海常住人口，用于统一校准 |
| 690ms → 54.6ms | 10M 数据 `ST_DWithin` 无索引 vs GiST |
| 220ms → 0.024ms | 10M 数据实时聚合 vs 物化视图 |
| 227KB → 49.7KB | 真实数据同范围 GeoJSON vs MVT |
| P95 8.5ms | 真实数据周边接口串行 50 次 |
| 181 QPS | JMeter 50 并发 × 20 次 |

> 所有效果数字都是本机实测；换环境需要重新压测，不把单机数字当生产容量。

## 8. 前端展示怎么走

```
页面
  ├─ 底图：World_Imagery（WGS84 页面）/ 高德（GCJ 页面），maxZoom 18
  ├─ POI：按 category 配色 + 图例
  ├─ Agent：intent/agentType/engine/tools/latency + 执行轨迹 + trace link
  ├─ 生活圈：绿色覆盖格 / 红色盲区格 + 摘要
  └─ 多路线：6 条路线多色 + 路线卡片
```

Agent 秒回的解释：空间查询走 `ToolRegistry` 的确定性 SQL 工具，不经过 LLM；22ms 属于正常范围。
