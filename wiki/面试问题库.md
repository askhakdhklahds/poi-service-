## A. 项目总览

**【P0】1. 介绍一下这个项目。**

回答要点：城市 POI 空间分析平台；真实 85,864 POI + 16 区 + 10M 压测；双列坐标 + GiST；周边/最近邻/统计/MVT/GeoServer；EchoMind 风格 Agent；15 分钟生活圈；多路线对比。

**【P0】2. 项目解决什么实际问题？**

回答要点：附近有什么、某区域设施怎么分布、居民 15 分钟能不能到、从 A 到 B 开车/步行怎么走、路上有什么。

**【P1】3. 项目有哪些模块？**

回答要点：数据入库、空间查询、行政区统计、MVT/GeoServer、异步导入、Agent、生活圈、多路线、安全/监控/测试/部署。

**【P0】4. 项目技术栈？**

回答要点：Java 17 / Spring Boot 3.4.5 / Spring JDBC / PostgreSQL 17.11 / PostGIS 3.6.2 / pgRouting 4.0 / Redis(Memurai) / Caffeine / GeoServer 3.0 / MapLibre / Docker。

**【P0】5. 你在项目里负责什么？**

回答要点：独立完成数据入库、查询、分析、瓦片、Agent、生活圈、多路线、测试和文档；按真实实现说，不夸大。

**【P1】6. 项目的目录结构？**

回答要点：`controller`、`service`、`agent`、`config`、`security`、`db/migration`、`scripts`、`static`、`wiki`。

**【P1】7. 项目怎么启动？**

回答要点：启动 PostgreSQL/Memurai；`mvn spring-boot:run`；8081；GeoServer 8080。

**【P1】8. 数据量多大？**

回答要点：85,864 真实 POI、16 区、10,010,000 合成压测、15,237 人口网格、81,481 驾车边、77,965 步行边。

## B. 数据与建模

**【P0】11. POI 数据从哪来？**

回答要点：OSM France 上海提取 PBF；ogr2ogr + `osmconf_poi.ini` 导入 `osm_points`；`load_osm_poi.sql` 按标签筛出 85,864 条。

**【P0】12. 分类怎么来的？**

回答要点：OSM `amenity/shop/tourism/leisure/office/healthcare/public_transport` 映射成 8 大类；`add_sub_category.sql` 再分 38 个大类/小类组合。

**【P0】13. 行政区数据怎么清洗？**

回答要点：`ST_MakeValid` 修自相交，`ST_CollectionExtract(...,3)` 取面，`ST_Multi` 统一 MultiPolygon，`ST_Transform(...,4549)` 生成米制列。

**【P1】14. 为什么行政区用 MultiPolygon？**

回答要点：一个区可能有飞地、岛屿、边界碎片；MultiPolygon 能装多个面。

**【P1】15. `district` 主键是什么？**

回答要点：`id` 自增主键；`adcode` 是唯一业务键。不是 adcode 主键。

**【P1】16. `source_id` 有什么用？**

回答要点：导入幂等键，如 `osm_123`；唯一索引 + `ON CONFLICT DO NOTHING`，重复导入不重复插入。

**【P0】17. 为什么 `poi` 有 `lng/lat` 又有 `geom`？**

回答要点：`lng/lat` 方便导出/前端；`geom` 是空间类型，负责索引和空间函数。

**【P1】18. 为什么用 Flyway？**

回答要点：建表/补列/索引版本化，可重复执行，新环境一键迁移。

**【P1】19. V1 和 V3 是什么关系？**

回答要点：V1 初始表；V3 补 `sub_category`、唯一索引，兼容旧库；最终表是 V1+V3 合并后的结构。

**【P0】20. 10M 压测数据是真实的吗？**

回答要点：不是，`poi_bench` 是程序生成的合成点，只做规模压测；演示/业务用真实 85,864 POI。

**【P0】21. 人口数据从哪来？**

回答要点：WorldPop 2020 中国 1km，CC-BY-4.0；`worldpop_to_grid.py` 裁剪上海并生成 15,237 个网格。

**【P0】22. 为什么人口要校准？**

回答要点：1km 旧版是未约束估计，上海区县合计约 3,220 万；按 2020 年七普 24,870,895 统一校准；统一缩放不改变覆盖率。

**【P1】23. 路网怎么构建？**

回答要点：OSM 路网 → `road_raw` 211,721 边 → 构建节点和 source/target → 最大连通分量 `road_main` 84,203 边。

**【P0】24. 为什么路网要先取最大连通分量？**

回答要点：图不连通时 `pgr_dijkstra/pgr_ksp` 返回空路径；先取最大连通分量保证起终点可达。

**【P0】25. 驾车/步行路网怎么拆？**

回答要点：`road_car` 过滤可驾车道路，按 maxspeed/等级算时间，oneway 控制方向；`road_walk` 过滤可步行道路，1.2m/s，台阶 0.8m/s；`road_walk_all` 作为回退。

## C. 空间查询与索引

**【P1】26. geometry 和 geography 的区别？**

回答要点：geometry 平面计算，单位取决于 SRID；geography 球面计算，单位米但更重、索引受限。项目用“4326 geometry + 4549 投影列”。

**【P1】27. 4326 算距离为什么错？**

回答要点：单位是度；不同纬度 1 度经度对应距离不同。

**【P0】28. 为什么存 4326 和 4549 两列？**

回答要点：4326 交换/展示/点面归属；4549 米制距离。每次 `ST_Transform` 会让索引失效，所以预计算成列。

**【P1】29. 上海为什么用 4549？**

回答要点：CGCS2000 3 度带，中央经线 120°E，单位米；北京 4548、武汉 4547、东北 4550。

**【P0】30. GiST 是什么？**

回答要点：通用搜索树，PostGIS 用它实现 R 树；MBR 粗筛 + 精确判断，即 filter-and-refine。

**【P0】31. 为什么用 `ST_DWithin` 不用 `ST_Distance < x`？**

回答要点：`ST_DWithin` 能用 GiST 做包围盒预筛；`ST_Distance < x` 必须逐行精算，无法走索引。

**【P0】32. 10M 数据 690ms→54.6ms 怎么测的？**

回答要点：同一张 10M 表、同一条 SQL；先 DROP INDEX + EXPLAIN 得 Parallel Seq Scan 690ms；建 GiST 后 Bitmap Index Scan 54.6ms；热缓存约 22ms。

**【P1】33. KNN `<->` 怎么工作？**

回答要点：GiST 距离排序算子，走索引只读最近 N 行；10M 数据 0.37ms。

**【P2】34. `within` 为什么按 distance_m 排序，`nearest` 用 `<->`？**

回答要点：`within` 已被半径过滤，结果集有限，可按精确距离排序；`nearest` 不设半径，用 KNN 索引取最近 N 个。

**【P2】35. 为什么先 `ST_Transform` 参数点？**

回答要点：参数只有一行，转一次；对表列 `ST_Transform` 会让每行都算，且索引失效。

**【P2】36. 索引失效场景有哪些？**

回答要点：列上套函数、列上 `ST_Transform`、`geom::geography`、SRID 不一致、统计信息过期。

**【P2】37. 为什么 4326 和 4549 都建 GiST？**

回答要点：4326 用于范围/相交/点面；4549 用于米制距离/排序。

**【P2】38. 复合索引 `(category, geom_4549)` 什么时候用？**

回答要点：先按分类等值过滤，再做空间范围查询；比单列空间索引更有选择性。

**【P2】39. 点面归属怎么做？**

回答要点：`ST_Contains(d.geom, p.geom)`；`district.geom` 有 GiST 索引。

**【P2】40. 深分页怎么优化？**

回答要点：键集分页（`WHERE id > ?`），避免大 OFFSET。

## D. 物化视图与缓存

**【P0】41. 物化视图和普通视图区别？**

回答要点：普通视图保存 SQL，每次重算；物化视图保存结果，查询快但需要刷新。

**【P0】42. 220ms→0.024ms 怎么来的？**

回答要点：实时 JOIN + `ST_Contains` + 聚合 220ms；物化视图预聚合 16 行，查询 0.024ms。

**【P1】43. `REFRESH ... CONCURRENTLY` 的前提？**

回答要点：物化视图上要有唯一索引；不锁读，但刷新更慢、需要额外空间。

**【P1】44. 物化视图刷新成本？**

回答要点：10M 数据全量构建约 4 分 6 秒；适合定时/低峰刷新。

**【P0】45. 为什么有了物化视图还要 Redis？**

回答要点：物化视图减少数据库计算；Redis 减少数据库访问；两层不同问题。

**【P2】46. 缓存一致性怎么保证？**

回答要点：短 TTL + 刷新物化视图时清缓存；导入数据后手动刷新或清缓存。

**【P2】47. 为什么统计用 Redis、瓦片用 Caffeine？**

回答要点：统计跨实例共享、变化慢；瓦片体积大、访问频繁、允许本地不一致。

**【P2】48. 缓存穿透/空值怎么处理？**

回答要点：`cache-null-values: false`；对不存在的数据返回 400/404，不缓存空结果。

## E. MVT 与 GeoServer

**【P1】49. MVT 是什么？**

回答要点：Mapbox Vector Tile，Protobuf 二进制矢量瓦片；只返回视口内数据。

**【P0】50. MVT 为什么比 GeoJSON 小？**

回答要点：视口裁剪 + 二进制编码 + 属性名只存一次；真实数据 227KB→49.7KB。

**【P1】51. `ST_AsMVTGeom` 的参数？**

回答要点：几何、瓦片范围、`extent=4096`、`buffer=256`、`clip=true`。

**【P2】52. 动态 MVT 和预生成瓦片区别？**

回答要点：动态每次查库，适合变化数据；预生成读磁盘，适合稳定数据/高并发/CDN。

**【P2】53. MVT 动态瓦片怎么缓存？**

回答要点：Caffeine，键 `z/x/y/category`，1 万张/10 分钟，`X-Tile-Cached` 头。

**【P2】54. GeoServer 怎么发布？**

回答要点：workspace → PostGIS datastore → 发布表/视图 → SRS/BBox → 样式 → 预览；也可 REST 自动发布。

**【P0】55. WMS/WFS/WMTS 区别？**

回答要点：WMS 返回图片；WFS 返回矢量要素；WMTS 返回预切瓦片。

**【P2】56. GeoServer 多几何列的坑？**

回答要点：同一表多个 geometry 列，BBox 可能混用 4326/4549，预览空白；发布单几何列视图或手动修正 BBox。

**【P2】57. 图层组是什么？**

回答要点：多个图层的逻辑组合，不复制数据；列表顺序即渲染顺序。

**【P2】58. GCJ-02 偏移怎么解决？**

回答要点：GCJ-02 不是 EPSG 坐标系，`ST_Transform` 处理不了；用偏移算法生成 `poi_gcj` 和 `tiles-gcj`。

## F. 异步导入与线程池

**【P1】59. 为什么导入要异步？**

回答要点：大文件耗时，先返回 taskId，前端轮询；任务状态写 `import_task`。

**【P0】60. 为什么先 COPY 到 staging？**

回答要点：COPY 快速卸货；几何生成/校验/去重放一条 `INSERT ... SELECT`。

**【P1】61. `ON CONFLICT (source_id)` 作用？**

回答要点：幂等去重，重复导入跳过已存在行。

**【P0】62. Batch 和 COPY 哪个快？**

回答要点：5 万行逐条 14.7s、Batch 6.8s、COPY+staging 9.8s；这里 COPY 多一次转换，所以 Batch 更快；核心结论是批量远快于逐条。

**【P0】63. 线程池参数怎么定？**

回答要点：`importExecutor` core 2 / max 4 / queue 50；IO/DB 密集型，保守配置；生产加优雅关闭、拒绝策略、监控。

**【P2】64. 线程池拒绝策略？**

回答要点：默认 AbortPolicy，第 55 个任务抛 `TaskRejectedException`；生产可 CallerRuns 或持久化任务重试。

**【P2】65. 优雅停机怎么做？**

回答要点：`setWaitForTasksToCompleteOnShutdown(true)` + `setAwaitTerminationSeconds(60)`；当前没配，是不足。

**【P2】66. 并发导入有什么问题？**

回答要点：`TRUNCATE poi_staging` 是全局的，并发会互相踩；生产按 taskId 隔离 staging 或加锁。

## G. Agent

**【P0】67. Agent 整体流程？**

回答要点：Controller → Orchestrator → 改写 → 意图 → 路由 → 角色 → 工具 → 校验 → 汇总 → 记忆 → 轨迹/监控。

**【P0】68. 为什么只保留 4 大类意图？**

回答要点：顶层意图只负责路由；查询内部用 `entities.scene` 区分附近/最近/统计/排名/对比；避免意图爆炸。

**【P0】69. 意图和角色的映射？**

回答要点：QUERY→SPATIAL_QUERY；ROUTE→ROUTE_PLANNING；REPORT→REPORT；GENERAL→GENERAL。

**【P0】70. 意图识别怎么做的？**

回答要点：关键词优先 + 可选 LLM；抽取地点/分类/半径/数量/from/to；LLM 失败回退关键词。

**【P1】71. 为什么不让 LLM 直接判断所有意图？**

回答要点：关键词确定性高、零成本、可解释；LLM 适合处理边界情况，失败可回退。

**【P0】72. 角色契约为什么放 profiles.json？**

回答要点：角色差异配置化；新增角色只改枚举、配置、Bean；Orchestrator 自动收集并校验。

**【P1】73. BaseAgent 的模板方法？**

回答要点：`run` 负责 LLM/确定性分支、失败回退、补元数据；子类只实现 `executeDeterministic`。

**【P1】74. 为什么只有 GENERAL 开 LLM？**

回答要点：空间查询/路线/报告要求确定性；LLM 适合问候/兜底；配置可改，但要有回归测试。

**【P1】75. ToolRegistry 做了什么？**

回答要点：工具注册、角色白名单、必填参数、超时、错误封装、耗时统计。

**【P1】76. 工具超时怎么实现？**

回答要点：`CompletableFuture.supplyAsync(...).get(timeoutMs, MILLISECONDS)`；超时返回 `ToolResult.fail`。

**【P1】77. 工具失败怎么办？**

回答要点：返回 fail，Agent 生成“工具调用失败”；监控记录失败率；不会让整个请求 500。

**【P0】78. 多轮记忆怎么实现？**

回答要点：sessionId→ConversationState；最近 12 条 + 上下文 place/lon/lat/radius/category；追问改写。

**【P1】79. “那餐厅呢”怎么接上？**

回答要点：rewrite 检查上下文有地点、问题是追问词，补成“在黄浦区附近 那餐厅呢 餐饮”。

**【P0】80. 怎么防幻觉？**

回答要点：提示词禁止编造；工具返回真实数据；AnswerVerifier 检查空答案/无工具证据/NaN。

**【P1】81. AnswerVerifier 做了什么？**

回答要点：空答案、无工具证据、`NaN/Infinity`；数据类意图必须有工具调用；不是完整 LLM-as-Judge。

**【P1】82. 怎么观测 Agent？**

回答要点：steps（工具/输入/输出/耗时）、TraceStore（requestId→轨迹）、AgentMonitor（成功率/耗时/角色调用数）。

**【P1】83. 为什么复杂意图走确定性？**

回答要点：比较/路线/排名对计算正确性要求高；SQL 可复现、可解释；LLM 容易算错。

**【P1】84. 新增一个工具要改什么？**

回答要点：`ToolRegistry.registerTools` 加 ToolDefinition + handler；不用改 Agent。

**【P1】85. 新增一个角色要改什么？**

回答要点：AgentType 加枚举；profiles.json 加契约；新建 `@Component` 继承 BaseAgent；Orchestrator 自动收集。

**【P2】86. 两套工具系统的问题？**

回答要点：`LlmAgentClient` 还有自己的工具循环；和 ToolRegistry 是两套；下一步统一到 ToolRegistry。

**【P1】87. 记忆为什么放内存？**

回答要点：演示够用；生产换 Redis + TTL；当前重启丢失，是已知不足。

**【P1】88. Agent 怎么控制成本？**

回答要点：只有 GENERAL 开 LLM；工具结果截断 20 条；温度 0.1；最多 2 轮工具；规则/工具兜底。

**【P1】89. 怎么测试 Agent？**

回答要点：IntentRecognizerTest 测意图；MockMvc 测 Controller；手工/脚本测四类问题和多轮；监控/trace 验证。

**【P1】90. 最大风险是什么？**

回答要点：LLM 不稳定、工具超时、记忆丢失、意图误判；通过回退、超时、确定性路径、校验降低风险。

## H. 生活圈

**【P0】91. 生活圈解决什么问题？**

回答要点：居民 15 分钟内能不能到设施、覆盖多少人口、哪里是盲区。

**【P0】92. 人口网格怎么来的？**

回答要点：WorldPop 2020 中国 1km → 裁剪上海 → 15,237 个网格；`ST_Contains` 归属行政区。

**【P1】93. 为什么按人口加权？**

回答要点：网格人口不同；覆盖率应是“覆盖人口/总人口”，不是“覆盖格子/总格子”。

**【P0】94. 覆盖率怎么算？**

回答要点：`ST_DWithin(poi.geom_4549, grid.geom_4549, radius)`；`radius = thresholdSeconds × 1.2`；汇总 popTotal/popCovered。

**【P0】95. 盲区怎么找？**

回答要点：`covered=false` 且人口 > 0 的网格；返回红色 FeatureCollection；人口多但未覆盖优先。

**【P2】96. 为什么校准人口？**

回答要点：WorldPop 1km 旧版未约束估计偏高；按七普 24,870,895 统一校准；覆盖率不变。

**【P2】97. 生活圈是路网还是直线？**

回答要点：当前欧氏半径，MVP；下一步 `pgr_drivingDistance` 做路网等时圈。

**【P2】98. 前端怎么可视化？**

回答要点：`life-circle.html`；选行政区/设施/5-10-15 分钟；绿色覆盖格、红色盲区格；摘要卡片；CDP 验证截图。

**【P2】99. 数据局限？**

回答要点：1km 粗、人口模型估计、设施分类有限、欧氏半径、不是真实出行调查。

**【P2】100. 为什么黄浦 97.2%、浦东 31.9%？**

回答要点：黄浦面积小、设施密集；浦东面积大、设施分布不均；这是模型结果，不是官方统计。

## I. 多路线

**【P0】101. 多路线解决什么问题？**

回答要点：A→B 给几条驾车/步行路线，地图显示，并说明沿途特点。

**【P0】102. 车/人怎么区分？**

回答要点：不是前端切开关；`road_car` / `road_walk` 两套路网，道路过滤、速度、oneway 约束不同。

**【P1】103. 为什么需要 `road_walk_all`？**

回答要点：可步行路网过滤后可能不连通；回退到全市路网，快速路/主干道加 3 倍成本。

**【P0】104. 多路线怎么做的？**

回答要点：首选 Valhalla 高精度路网（`costing=auto|pedestrian`、备选路线、polyline6）；失败/超时回退本地 `pgr_ksp`；本地取 K 条候选，边集合 Jaccard >0.8 去重；最多 3 驾车 + 3 步行；沿途 POI/行政区由本地 PostGIS 富化。

**【P0】105. 沿途特点怎么算？**

回答要点：道路构成按 highway 分组（Valhalla 路线缺省）；150m 缓冲统计 POI；`ST_Intersects` 统计行政区；拼摘要。

**【P0】106. 为什么路线时间是估算？**

回答要点：没有实时路况/红绿灯/转向限制；Valhalla 用标称速度，本地 maxspeed 大量为空；只能估算，不能当生产导航。

**【P1】106a. 为什么接 Valhalla，不自己算？**

回答要点：自建路网只是 OSM 子集，maxspeed/oneway 缺失多，路线质量差；Valhalla 用完整 OSM 和成熟代价模型。外部服务只负责几何/距离/时间，富化仍在本地；8s 超时 + 空结果回退，保证可用性。

**【P2】107. 路线接口性能？**

回答要点：Valhalla 冷启动 1.1–2.3s；Redis 命中约 60ms；本地兜底冷启动约 688ms、缓存 P50 3.73ms。

**【P2】108. Agent 怎么接多路线？**

回答要点：IntentRecognizer 抽 from/to；RoutePlanningAgent → route_compare；返回 answer/cards/routePlanUrl；agent.html 显示链接。

**【P1】108a. 路线页的地名输入怎么实现？**

回答要点：输入 220ms 防抖 → `GET /api/poi/search`；SQL 用 `ILIKE` 同时查 POI 与行政区，精确匹配优先、短名称优先；下拉选择后按经纬度打点并 `flyTo`，起终点齐全自动规划；前端同名去重、HTML 转义；后端参数化查询防注入。

**【P2】109. 为什么用 pgr_ksp 不用多次 pgr_dijkstra？**

回答要点：KSP 一次返回 K 条候选，效率更高；再用 Jaccard 保证多样性。

**【P2】110. 路线不连通怎么办？**

回答要点：先试 Valhalla；失败回退本地，步行再回退 `road_walk_v2` → `road_walk` → `road_walk_all`；都失败返回空路线和提示。

## J. 工程化/安全/测试/部署

**【P0】111. JWT 怎么工作？**

回答要点：登录签发 token（用户名、角色、过期）；请求带 `Authorization: Bearer`；无状态校验。

**【P1】112. JWT 和 session 区别？**

回答要点：JWT 无状态，适合前后端分离/多实例；session 要服务端存储。

**【P0】113. RBAC 怎么设计？**

回答要点：admin/analyst/viewer；`/api/admin/**`→ADMIN；`/api/import/**`→ADMIN/ANALYST；读接口公开。

**【P0】114. 限流怎么做？**

回答要点：Bucket4j 令牌桶，每 IP 120/分钟；超限 429；当前内存，多实例要 Redis。

**【P1】115. 测试怎么分层？**

回答要点：JwtService 单测；MockMvc 参数/权限；Testcontainers 真实 PostGIS；无 Docker 自动跳过。

**【P1】116. 为什么用 Testcontainers 不用 H2？**

回答要点：H2 没有 PostGIS 的 ST_DWithin/GiST/ST_Contains；测了不能证明生产可用。

**【P1】117. 怎么监控？**

回答要点：Actuator health/metrics/prometheus；瓦片命中率 Gauge；慢查询；Agent monitor/trace。

**【P1】118. 怎么部署？**

回答要点：Dockerfile 多阶段；compose 起 app/postgres/redis/geoserver/prometheus/grafana；CI `mvn verify`。

**【P1】119. 怎么保证接口安全？**

回答要点：JWT/RBAC、参数校验、半径/limit 夹取、限流、只允许白名单工具；生产收紧 CORS、密钥放环境变量。

**【P1】120. 项目怎么测试的？**

回答要点：18 个自动化用例；30 个手工/脚本功能用例；功能测试报告含真实数据；页面用 CDP 截图验证。

## K. 难点/不足/改进

**【P0】121. 最大难点？**

回答要点：坐标系单位错误、10M 全表扫描、路网不连通、GeoServer 多几何列 BBox、LLM 分类不一致、Agent 工具循环。

**【P2】122. 坐标系单位错误怎么发现？**

回答要点：最早在 4326 上算距离，结果单位是“度”；用 geography 验证后改为 4549 投影列。

**【P2】123. 10M 全表扫描怎么优化？**

回答要点：EXPLAIN 发现 Seq Scan；改 ST_DWithin + GiST；690ms→54.6ms。

**【P2】124. 路网不连通怎么解决？**

回答要点：pgr_dijkstra 返回 0 条边；构建最大连通分量 `road_main`；步行再加 `road_walk_all` 回退。

**【P2】125. GeoServer 预览空白怎么解决？**

回答要点：多几何列导致 BBox 混用；发布单几何列视图或手动修 BBox。

**【P2】126. LLM 分类不一致怎么解决？**

回答要点：LLM 说“餐厅”，库里是“餐饮”；GisTools `normalizeCategory` 归一化。

**【P0】127. 项目有哪些不足？**

回答要点：记忆在内存、生活圈欧氏半径、1km 人口、步行回退、并发导入、单机压测、内存用户。

**【P0】128. 下一步改进？**

回答要点：Redis 会话、pgr_withPoints、路网等时圈、2SFCA、补点推荐、分区表、增量物化视图、统一工具系统、LLM-as-Judge。
