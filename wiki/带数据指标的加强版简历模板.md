## 三、简历模板（强指标版）

```text
城市 POI 空间分析平台
技术栈：Java 17 / Spring Boot 3.4 / Spring JDBC / PostgreSQL 17 + PostGIS 3.6 / pgRouting / Redis / Caffeine / GeoServer / MapLibre / Docker

- 设计 4326 + 4549 双列坐标模型与 GiST 索引，10M 压测数据 ST_DWithin 由 690ms 降至 54.6ms（冷）/约 22ms（热），KNN 0.37ms；真实数据周边接口 P95 8.5ms。
- 用物化视图把 10M 数据行政区统计从 220ms 降到 0.024ms，叠加 Redis 后接口 25ms；MVT 让同范围瓦片体积从 227KB 降到 49.7KB（降 78.6%）。
- 设计 CSV 异步导入（COPY + staging + ON CONFLICT 幂等），5 万行逐条/Batch/COPY 三种方式实测 14.7s / 6.8s / 9.8s，并如实说明 COPY 因多一次转换而非最快。
- 重构 EchoMind 风格分层 Agent：Orchestrator + Intent + Profiles + BaseAgent + ToolRegistry + Memory + Verifier + Trace/Monitor；4 角色、11 工具、4 顶层意图，LLM 只负责表达，空间计算交给确定性 SQL。
- 新增 15 分钟生活圈评估：WorldPop 1km → 15,237 个网格（9,422 个在区内），按七普 24,870,895 人校准；黄浦区医疗覆盖率 97.2%，浦东新区 31.9%，覆盖接口 17–245ms。
- 设计多路线对比：首选 Valhalla 高精度路网（auto/pedestrian + 备选路线），失败自动回退本地 road_car / road_walk_v2 + pgr_ksp + Jaccard 去重；人民广场→外滩驾车 2.9km/11min、步行 2.0km/27min，3+3 条；每条统计道路构成、150m 沿途 POI 和经过行政区；缓存命中约 60ms。
- 前端按 POI 分类配色 + 图例，Agent 展示意图/角色/工具/耗时/执行轨迹；底图切 World_Imagery 并限制 z18，解决高缩放占位图。
```

## 四、指标怎么讲

### ST_DWithin 优化

- 同一张 10M 表、同一条 SQL：先 `DROP INDEX` + `EXPLAIN ANALYZE` 得 Parallel Seq Scan 690ms；建 GiST 后得 Bitmap Index Scan 54.6ms；热缓存约 22ms。
- 不拿 SQL 层数字冒充接口指标；接口 P95 50.9ms 包含 `ST_AsGeoJSON`、JSON 序列化、网络和连接开销。

### 物化视图

- 实时 JOIN + 聚合 220ms；物化视图查 16 行 0.024ms。
- 全量构建 4 分 6 秒，`REFRESH ... CONCURRENTLY` 需要唯一索引，不锁读但刷新更慢。
- 物化视图减少数据库计算，Redis 减少数据库访问，是两层。

### MVT

- 同范围 GeoJSON 227KB vs MVT 49.7KB；体积下降来自视口裁剪 + 二进制编码 + 属性名只存一次。

### 生活圈

- 人口数据：WorldPop 2020 1km，CC-BY-4.0；旧版未约束估计偏高，按七普总人口统一校准；统一缩放不改变覆盖率。
- 覆盖半径：步行 1.2 m/s，5/10/15 分钟 → 360/720/1080 米；这是评估口径，不是真实路径规划。
- 当前是欧氏覆盖，下一步接 `pgr_drivingDistance` 做路网等时圈。

### 多路线

- 首选 Valhalla（`costing=auto|pedestrian`，备选路线，polyline6），8s 超时；失败回退本地。
- 本地车/人两套路网：`road_car` / `road_walk_v2`；步行不连通时逐级回退 `road_walk` / `road_walk_all`。
- `pgr_ksp` 多候选 + Jaccard 去重；最多 3 条驾车 + 3 条步行。
- 人民广场→外滩：Valhalla 驾车 2.9km/11min、步行 2.0km/27min；外部接口 1.1–2.3s，缓存命中约 60ms。
- 时间是估算值，不含实时路况、红绿灯和转向限制；公共 Valhalla 不适合生产，需自建。

## 五、不能乱说的数字

- 不要说自己做了“生产级高并发”；本机是 50 并发、单机环境。
- 不要把 1000 万合成数据说成真实业务数据。
- 不要把生活圈覆盖率说成“真实居民出行调查结果”；它是人口栅格 + 设施点位的模型估计。
- 不要把路线时间说成真实导航时间；没有实时路况和红绿灯数据。
- 不要说路线引擎完全自研：首选是公共 Valhalla/OSM，本地 pgRouting 是兜底；生产需自建。
- 不要编没有测过的 QPS、准确率、召回率。
