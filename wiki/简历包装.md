# 简历包装

## 项目定位

不要写成“POI 查询 Demo”，建议定位为：

> **GIS 后端 + 空间分析 + Agent 工程**：一个能支撑“附近查询、地图服务、行政区统计、15 分钟生活圈评估、自然语言空间问答”的城市空间数据平台。

## 一句话描述

> 基于 Spring Boot 3 + PostgreSQL/PostGIS 的城市 POI 空间分析平台：导入 85,864 条真实上海 OSM POI 与 16 个真实行政区，设计 4326 + 4549 双列模型与 GiST 索引，支持周边/最近邻/缓冲区/行政区统计、MVT 矢量瓦片、GeoServer WMS/WFS、pgRouting 路网，以及 EchoMind 风格的分层空间 Agent；新增基于 WorldPop 人口的 15 分钟生活圈覆盖评估。

## 2 分钟项目介绍

> 我做的是一个城市 POI 空间分析平台，解决“附近有什么、某个区域的设施怎么分布、居民 15 分钟内能不能到”这类问题。
>
> 数据侧导入了 85,864 条真实上海 OSM POI 和 16 个真实行政区，另外用 1000 万条合成数据做规模压测；设计了 4326 存储 + 4549 米制投影的双列模型，并建 GiST 索引。
>
> 查询侧周边用 ST_DWithin，因为能用 GiST 做包围盒预筛；最近邻用 <-> KNN。真实数据接口 P95 8.5ms；1000 万数据从无索引 690ms 优化到 54.6ms。
>
> 统计侧行政区实时聚合要 220ms，我用物化视图降到 0.024ms，再叠 Redis，接口 25ms。
>
> 地图侧用 ST_AsMVT 出矢量瓦片，体积比 GeoJSON 降 75%~79%；GeoServer 通过 REST 自动发布 WMS/WFS。
>
> Agent 侧我参考 EchoMind 的结构做了精简重构：Orchestrator 负责意图、路由、执行、校验、汇总；四个角色分别处理通用问答、空间查询、路线规划和报告；工具通过 ToolRegistry 做白名单、超时和统计；LLM 只负责理解和表达，空间计算全部交给确定性 SQL 工具，避免幻觉。
>
> 最近还加了一个 15 分钟生活圈评估：把 WorldPop 人口落到 1km 网格，按七普人口校准，用 ST_DWithin 算覆盖率和盲区。比如黄浦区医疗 15 分钟覆盖率 97.2%，浦东新区只有 31.9%，能直接看出设施分布不均。
>
> 路线侧做了 A→B 多路线对比：首选 Valhalla 高精度路网，失败自动回退本地车/步行两套路网 + pgr_ksp；地图多色显示，并统计道路构成、沿途 POI 和经过行政区。人民广场到外滩，驾车约 2.9km/11 分钟、步行约 2.0km/27 分钟，缓存命中约 60ms。
>
> 整体是 Spring Boot 3 + PostGIS + Redis + Docker Compose，能部署、能监控、能测试。

## 常见追问

### 为什么存两份坐标？

4326 负责交换和展示，4549 负责米制距离；每次 `ST_Transform` 会让索引失效，所以预计算成列。

### 为什么 ST_DWithin 比 ST_Distance 快？

`ST_DWithin` 可以用 GiST 做包围盒预筛，`ST_Distance < x` 必须逐行精算。

### 物化视图算作弊吗？

不算，是典型空间预聚合；代价是刷新慢，适合定时/低峰刷新。

### Agent 为什么不让 LLM 直接算？

LLM 容易算错距离、编坐标；空间计算交给 PostGIS，LLM 只组织语言，结果可复现、可解释。

### 生活圈的人口数据可靠吗？

WorldPop 是公开人口估计，1km 旧版偏高，我按 2020 年七普 24,870,895 做了统一校准；覆盖率不受统一缩放影响。更高精度可以换 WorldPop 100m constrained 数据。

### 多路线怎么做的？

首选 Valhalla 高精度路网：`costing=auto|pedestrian`、支持备选路线，只取几何/距离/时间；失败或 8s 超时自动回退本地。本地用 `road_car` / `road_walk_v2` 两套路网：道路过滤、速度、`oneway` 约束都不同；`pgr_ksp` 取多条候选，按边集合 Jaccard 去重，最多 3 条驾车 + 3 条步行。每条路线再做 150m 缓冲统计沿途 POI，叠加道路构成和行政区。步行路网不连通时逐级回退并标注。这样既有路线质量，又不会被外部服务拖垮。

### 这个项目最大的难点？

坐标系单位错误、10M 全表扫描、路网不连通、GeoServer 多几何列 BBox、LLM 分类不一致、Agent 工具循环。
