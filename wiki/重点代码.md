# 重点代码

这份文档用于边看说明、边跟读源码。重点是每段代码接收什么、改了什么、为什么这样写，以及出问题时先看哪里。

## 1. 读代码顺序

1. `src/main/resources/application.yml`：端口、数据源、Redis、Agent 配置。
2. `src/main/resources/db/migration/V1~V4`：表、索引、双列模型、生活圈表。
3. `scripts/load_osm_poi.sql`、`add_sub_category.sql`、`import_districts.sql`：数据从哪来。
4. `controller/PoiController.java` → `service/PoiService.java`：核心空间 SQL。
5. `service/DistrictService.java` + `controller/AdminController.java`：物化视图 + 缓存。
6. `controller/TileController.java` + `service/GeoServerService.java`：MVT 与 OGC 服务。
7. `service/ImportService.java`：异步导入。
8. `agent/orchestrator/AgentOrchestrator.java` → `agent/role/*` → `agent/tool/ToolRegistry.java`：Agent 主链路。
9. `service/life_circle/CoverageService.java` + `controller/LifeCircleController.java`：生活圈评估。
10. `config/*`、`security/*`：限流、缓存、JWT、监控。

## 2. 数据层

### 双列模型

`db/migration/V1__init.sql`：

```sql
geom      geometry(Point, 4326) NOT NULL,
geom_4549 geometry(Point, 4549)
```

- `geom`：WGS84，负责交换、展示、点面归属。
- `geom_4549`：CGCS2000 3 度带，单位米，负责距离和面积。

### 索引

```sql
CREATE INDEX idx_poi_geom      ON poi USING GIST (geom);
CREATE INDEX idx_poi_geom_4549 ON poi USING GIST (geom_4549);
CREATE INDEX idx_poi_category  ON poi (category);
CREATE INDEX idx_poi_cat_4549  ON poi (category, geom_4549);
```

GiST 是 filter-and-refine：先按最小外接矩形粗筛，再精确判断。

### 数据导入

`scripts/load_osm_poi.sql`：

- OSM 标签 → 8 大类：餐饮、医院、学校、交通、购物、景点、商业、其他。
- 一次生成 `geom` 和 `geom_4549`。
- `source_id = 'osm_' || osm_id` 做幂等。

`scripts/add_sub_category.sql`：大类 → 小类（餐厅、咖啡、超市、公交站等）。

## 3. 核心查询

### 周边查询

`service/PoiService.java` 的 `within`：

```sql
WITH p AS (
  SELECT ST_Transform(ST_SetSRID(ST_MakePoint(?, ?), 4326), 4549) AS pt
)
SELECT id, name, category, sub_category,
       ROUND(ST_Distance(geom_4549, p.pt)) AS distance_m,
       ST_X(geom) AS lon, ST_Y(geom) AS lat,
       ST_AsGeoJSON(geom) AS geojson
FROM poi, p
WHERE ST_DWithin(geom_4549, p.pt, ?)
ORDER BY distance_m
LIMIT ?;
```

面试点：

1. `ST_DWithin` 能用 GiST 做包围盒预筛；`ST_Distance(...) < x` 必须逐行精算。
2. 只转参数点一次，不对表列做 `ST_Transform`。
3. Controller 把半径夹在 1–50km、limit 夹在 1–500。

### 最近邻

```sql
ORDER BY geom_4549 <-> p.pt LIMIT ?;
```

`<->` 是 GiST 距离算子，走 KNN 索引。

### 点面归属

```sql
SELECT p.id, p.name, d.name AS district_name
FROM poi p
LEFT JOIN district d ON ST_Contains(d.geom, p.geom)
WHERE p.id = ?;
```

## 4. 物化视图与缓存

`service/DistrictService.java`：

```java
@Cacheable(value = "districtStats", key = "#adcode")
public Map<String, Object> stats(String adcode) {
    try {
        // 先查 mv_district_stats
    } catch (DataAccessException ignored) {
        // 物化视图不存在时回退实时 JOIN
    }

```

`controller/AdminController.java` 的 `refreshStats`：

```sql
REFRESH MATERIALIZED VIEW CONCURRENTLY mv_district_stats;
```

- 前提：物化视图上有唯一索引。
- 效果：10M 数据实时聚合 220ms → 物化视图 0.024ms。（2026-11-16 复测：真实 85,864 POI 热缓存聚合 73–76ms → 物化视图 0.014ms。）
- 代价：全量构建约 4 分 6 秒，适合定时/低峰刷新。

## 5. MVT 与 GeoServer

`service/PoiService.java` 的 `tile`：

```sql
WITH bounds AS (SELECT ST_TileEnvelope(?, ?, ?) AS geom)
SELECT ST_AsMVT(q, 'poi', 4096, 'geom')
FROM (
  SELECT p.id, p.name, p.category,
         ST_AsMVTGeom(ST_Transform(p.geom, 3857), b.geom, 4096, 256, true) AS geom
  FROM poi p, bounds b
  WHERE ST_Intersects(p.geom, ST_Transform(b.geom, 4326))
  LIMIT 20000
) q;
```

- `extent=4096`：瓦片内坐标精度。
- `buffer=256`：边缘缓冲，防止裁切。
- `clip=true`：裁剪到瓦片。
- 真实数据 MVT 49.7KB vs GeoJSON 227KB，降约 78.6%。

`service/GeoServerService.java` 通过 REST 创建 workspace `poi`、datastore `poi_pg`、图层 `poi:poi` / `poi:district`。

## 6. 异步导入

`service/ImportService.java`：

```
上传 CSV → import_task(PENDING) → 返回 taskId
→ @Async("importExecutor")
→ COPY 进 poi_staging
→ INSERT INTO poi SELECT ... 生成 geom/geom_4549
→ ON CONFLICT (source_id) DO NOTHING
→ SUCCESS / FAILED
```

面试口径：COPY 不是永远最快；这里多了一次 staging → 正式表的几何转换，所以 JDBC Batch 更快。真实结论是“批量远快于逐条”。

## 8. 15 分钟生活圈

### 人口网格生成

`scripts/worldpop_to_grid.py`：

- 读取 WorldPop 1km GeoTIFF。
- 按上海行政区 bbox 裁剪。
- 输出 `grid_x, grid_y, lon, lat, pop`。
- WorldPop 是“每像元人数”，按块求和，不取平均。

### 导入

`scripts/load_population_grid.sql`：

- `\copy` 进 `population_grid_staging`。
- 生成 4326/4549 几何。
- 按 `ST_Contains(district.geom, cell.geom)` 归属行政区。
- 按七普总人口 24,870,895 统一校准。

### 覆盖计算

`service/life_circle/CoverageService.java`：

```sql
WITH covered AS (
  SELECT g.id, min(ST_Distance(p.geom_4549, g.geom_4549)) AS distance_m
  FROM population_grid g
  JOIN poi p ON ST_DWithin(p.geom_4549, g.geom_4549, ?)
  WHERE g.district_adcode = ? AND p.category = ?
  GROUP BY g.id
)
SELECT ... FROM population_grid g LEFT JOIN covered c ...
```

- 半径 = 步行秒数 × 1.2 m/s。
- 输出 `popTotal / popCovered / coverageRatio / gapPopulation` + FeatureCollection。
- Redis 缓存键 `adcode:category:threshold`。

## 9. 多路线对比

- `service/route/ValhallaRouteService.java`：首选高精度路线。`RestClient` POST `/route`，`costing=auto|pedestrian`，`alternates`，解析 `shape`（polyline6）；异常/超时返回空列表。返回 `source=valhalla`、`sourceLabel=高精度路网`。
- `service/route/RoutePlanService.java`：`externalOrLocal()` 先调 Valhalla，空结果回退本地 `planMode()`；本地用 `pgr_ksp` 多路线、Jaccard 去重、道路构成、沿途 POI、行政区。
- `application.yml`：`route.valhalla.enabled/base-url/timeout-seconds`，默认开启、8s 超时。
- `db/migration/V5__route_network.sql`：`road_car` / `road_walk` 两套路网（本地兜底）。
- `db/migration/V6__walk_fallback.sql`：`road_walk_all` 步行回退路网。
- `db/migration/V7__walk_network_v2.sql`：`road_walk_v2`（76,824 边，排除 path/track，步行优先）。
- `controller/RouteController.java`：`POST /api/route/plan`。
- `static/route.html`：起点/终点**地名输入**（防抖调 `/api/poi/search`，下拉选点、自动定位与规划）+ 地图点选；带文字的起终点标签、路线总览、多路线地图 + 路线卡片（距离+预计时间+来源标签）；线宽 8/选中 10，车/人配色，步行虚线。
- `PoiService.searchPlaces` + `GET /api/poi/search`：POI 名称 `ILIKE` + 行政区名称，精确匹配优先，返回名称/分类/经纬度，参数化查询防注入。
- `IntentRecognizer.extractFromTo`：`(?:从)?(.+?)(?:到|→|->)(.+?)`，`从`可选。
- Agent：`ToolRegistry.route_compare` + `RoutePlanningAgent` 解析 from/to，返回 `routePlanUrl`。

## 11. 常见坑

1. `district` 主键是 `id`，`adcode` 是唯一业务键。
2. `sub_category` 和 `uq_poi_source_id` 在 V3 才补齐；新库 V1+V3 合并看。
3. `/api/poi/nearest` 当前没有暴露 `category` 参数。
4. 行政区名以“区/县”结尾时，`SpatialQueryAgent` 优先走 `district_center`，避免被 POI 名称抢先匹配。
5. 生活圈 SQL 必须返回 `{type:'FeatureCollection', features:[...]}`，不能只返回数组。
6. 新页面要同时加入 `SecurityConfig` 的静态资源放行列表。
7. 修改静态页面后，`mvn resources:resources` 才会复制到 `target/classes/static`。
8. Redis 缓存会缓存空结果；导入数据后先 `FLUSHDB` 或等 TTL 过期。
